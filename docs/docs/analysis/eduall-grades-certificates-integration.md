# EduAll Grades and Certificates Integration

## Scope

Phase 13 front-end integration adds EduAll dashboard surfaces for grade sheets, automatically calculated grade records and certificates while keeping business validation in the tested service layer.

## Template Analysis

The EduAll template areas reviewed before implementation were:

- dashboard shell fragments: `dashboard-sidebar.jspf`, `student-dashboard-sidebar.jspf`, `dashboard-topbar.jspf`, `dashboard-footer.jspf`, `flash-messages.jspf`;
- assessment management pages: `learning/assessment-list.jsp`, `assessment-form.jsp`, `assessment-builder.jsp`, `assessment-correction.jsp`;
- student assessment pages: `student/assessment-list.jsp`, `assessment-attempt.jsp`, `assessment-result.jsp`;
- attendance and schedule dashboards for form/table/card patterns;
- class group detail fragments, including planned grade sheet and exam result activity types;
- student dashboard fragments and cards for progress, results and certificate-style actions;
- public course/catalog pages and promotional certificate sections, which are not issuance or validation workflows.

Template decisions:

- reused `learning/attendance.jsp` as the runtime manager shell, with tabs for enrollments, grade sheets, certificates and attendance;
- reused the student attendance shell for the student grades/certificates view;
- kept dedicated `learning/grades-certificates.jsp` and `student/grades-certificates.jsp` as route targets/fallbacks, while navigation redirects to the attendance tabs for a single operational surface;
- added `public/certificate-validation.jsp` because validation is a public workflow outside the authenticated dashboard;
- did not reuse marketing/catalog certificate blocks because they do not support issuance, revocation or public code validation.

## New Routes

- `/learning/grades`: management route for administrators, coordinators and teachers; runtime navigation opens `/learning/attendance#grade-sheets`.
- `/learning/grades/sheets/{id}/configure`: updates class grade sheet assessment weights in any grade sheet state; each weight must be between 0 and 100, and totals different from 100 are saved with a warning.
- `/learning/grades/certificates/{id}/revoke`: revokes a published certificate.
- `/student/grades`: student consultation route for published grades and published certificates; runtime navigation opens `/student/attendance#grades-certificates`.
- `/certificates/validate`: public certificate validation by code.

There is no route or form for manually recording a final grade. Final grade records are snapshots produced by the lifecycle service from corrected assessment attempts and configured assessment weights.
The database trigger also rejects active grade records whose code is not generated by the automatic pattern (`AUTO-...` or compact `A-...`).

`AuthorizationPolicy` exposes only `/certificates/validate` as public. Management and student routes remain protected by the existing `/learning/*` and `/student/*` rules plus the service-level context checks.

## Back-end Linkage

The servlet `GradeCertificateServlet` uses:

- `GradeSheetService` for class grade sheet weight configuration and management reads;
- `GradeRecordService` for management and student grade listing;
- `EnrollmentService` and `ClassGroupEnrollmentService` for automatic draft grade sheet and certificate creation on active enrollments;
- `GradeRecordService`/`GradeLifecycleService` for automatic grade sheet publication after all required grades exist;
- `CertificateService` for automatic certificate publication, revoke, own-certificate listing and public validation;
- `GradeCertificateReadService` for read models, options and management listings.

The JSPs do not execute SQL and do not implement business rules. They receive view models:

- `GradeSheetView`;
- `GradeRecordView`;
- `CertificateView`;
- `CertificateValidationView`.

## Validation Behaviour

The front-end submits minimal forms and relies on services for:

- subject, class group and assessment coherence;
- assessment creation and update require a final-grade weight between 0 and 100;
- class grade sheet weight updates must include every configured assessment and each weight must be between 0 and 100;
- weight totals different from 100 keep the grade sheet incomplete and visible with a warning until corrected, or until the end of the class group period when the lifecycle service redistributes weights equally;
- final grade calculation from corrected assessment scores normalized to the grade sheet scale and multiplied by `based_on_assessment.weight`;
- no active final grade when any required assessment score is missing or any weight is missing/invalid;
- automatic publication only after every enrolled student has an automatically calculated final grade and every configured assessment has a corrected score;
- stale published grade sheets are synchronized back to Draft before management display/download if any displayed grade is still `-`;
- published grade sheets blocking direct grade changes while still allowing class assessment weight correction;
- certificate eligibility;
- certificate final grade calculated from published approved subject grade sheets using course ECTS;
- generated unique validation codes;
- one non-revoked certificate per course/student;
- manager access to every calculated certificate grade sheet;
- revoked certificates being excluded from public validation, student certificate access and direct downloads.

Management form option lists are scoped to the actor's grade/certificate management context. Teacher and coordinator pages do not expose unrelated students, class groups, subjects or assessment options, and student select labels avoid email addresses.

## Navigation

Menus were updated with `Grades & Certificates`:

- dashboard sidebar for non-student actors points to `/learning/grades`;
- dashboard sidebar for student-only context points to `/student/grades`;
- student dashboard sidebar points to `/student/grades`.

The active menu key is `grades`.

## Manual Test Notes

Recommended browser checks:

1. open `/learning/grades` as an authorized manager and confirm EduAll cards, forms and tables render without layout overlap;
2. enroll a student in a course/subject/class group and confirm the certificate/grade sheet appears as Draft without manual creation;
3. edit assessment weights from the class grade sheet pencil action in Draft or Published state;
4. correct only part of the required assessments and confirm missing `-` values keep the grade sheet in Draft with no active final grade for that student;
5. correct every required assessment and confirm the final grade is calculated from weights only when the configured weights total 100, and the grade sheet publishes automatically;
6. confirm the eligible certificate publishes automatically and exposes a validation link/code;
7. revoke the certificate and confirm `/certificates/validate?code=...` becomes invalid;
8. open `/student/grades` as the student and confirm only published grades and published certificates are visible;
9. open `/certificates/validate?code=...` without authentication and confirm only public certificate fields are displayed.

Operational note: `db.bootstrap.mode` is versioned as `none`. Use `schema`, `demo` or `full` only for intentional local reset/seed workflows.
